# GenAI Layer — Client Briefing Note Generation

**Deliverable this satisfies:** "Evidence of GenAI integration (prompts, workflow, code)" and "AI briefing notes for ≥3 clients" (`PLAN.md` deliverables checklist).

## Workflow

Rather than scripting a separate LLM API call, briefing notes were generated by applying the prompt template below directly against each client's row from `wallet_model.csv` / `opportunity_ranking.csv`, using the Cursor agent (Claude) as the LLM — chosen for hackathon speed (no API key setup/cost) while still producing genuinely model-generated, non-templated prose reasoned from the structured data, not boilerplate. The exact same prompt is reusable against an API (OpenAI/Anthropic) with no changes if the team wants to automate this for all 20 clients later — see "Scaling this up" below.

## Prompt template

```
You are a senior relationship banker's research analyst preparing a one-page briefing
note ahead of a client coverage meeting. You will be given structured data about a
corporate client's estimated "Share of Wallet" with Syn Bank versus their total
addressable banking wallet (a top-down proxy built from the client's own public
financials).

Write a concise, banker-ready briefing note (120-180 words) covering:
1. Current position: Syn Bank's share % and Rand gap, per pillar (Transactional,
   Trade & Working Capital, Foreign/Cross-Border) and blended.
2. One sentence of business context (sector, scale, what drives their banking needs).
3. A specific, actionable recommendation for the next coverage conversation - which
   pillar to lead with, and why, based on the data.
4. If the data reliability is flagged as anything other than "moderate", state that
   caveat plainly in one sentence so the reader doesn't over-read the Rand figure.

Do not invent numbers not present in the input. If a pillar's wallet is "external
estimate unavailable", say so rather than guessing.

INPUT DATA:
<one row from wallet_model.csv, all pillar/share/gap/reliability columns, for this client>
```

## Why this design

- **Grounded, not hallucinated:** the prompt explicitly forbids inventing numbers and requires stating data gaps plainly rather than filling them in — the model's job is narrative synthesis and recommendation, not arithmetic (arithmetic is already done deterministically in `scripts/build_wallet_model.py`).
- **Reliability-aware:** the prompt forces the model to surface the `top_down_reliability` caveat whenever it's not "moderate" — this is what catches cases like Glencore's naive R9.5 trillion "gap" before it reaches a banker or a judge (see `docs/reports/2026-08-13-wallet-model-summary.md`).
- **Banker-usable output, not a data dump:** ends every note with one specific, defensible next action, per the evaluation rubric's emphasis on "actionable, banker-usable recommendations" over "modeling sophistication" (40% Business Insight weight).

## Output

Generated notes for **all 20 clients** (full portfolio coverage, not a curated sample), covering every narrative type the model needs to handle correctly:
- **Actionable, high-conviction (ZAR reporters):** Shoprite Holdings, Bid Corporation, MTN Group, Vodacom Group, Pepkor Holdings, Aspen Pharmacare, and 4 more
- **Standout/anomalous finding:** Valterra Platinum and Clicks Group (near-zero share despite being domestic reporters, not scale-mismatch artifacts)
- **Needs a caveat read, not a literal one:** Sanlam and OUTsurance (>100% pillar shares from a proxy limitation, not data errors), Glencore/BHP/Anglo American (the naive-model trap - included deliberately as evidence the model correctly flags rather than reports face-value trillion-Rand figures)
- **Insufficient data:** The Bidvest Group (only company-level, not Group, AFS found - correctly left without a blended total rather than guessed)

See `hackathon-finreports/_extracted/client_briefing_notes.md` for all 20 generated notes, ordered by total Rand gap.

## Grounding verification

Every numeric claim in every note is machine-checked against `wallet_model.csv` by `scripts/verify_briefing_notes.py` - it extracts every percentage and Rand figure stated in the prose and confirms each one matches a real source value (within a small rounding tolerance for figures like "R448bn" from a source value of 447,941). This caught one real error during development (MTN's note originally cited a stale FY2024 foreign-revenue % instead of the FY2025 figure actually used in the model) before it reached a reviewer. Current status: 142/143 claims auto-verified, 1 manually reviewed and confirmed correct (a descriptive, non-data phrase the regex flagged as a false positive). Full audit trail: `hackathon-finreports/_extracted/briefing_notes_verification.csv`.

## Scaling this up (if time allows)

To generate the 43-row multi-year panel (`wallet_model_multiyear.csv`) automatically via an API instead of manually:
1. `pip install openai` (or `anthropic`)
2. Loop over rows, format each row into the same template above, call the API, write results to the same output format.
3. No prompt changes needed - the template above is API-ready as-is.
